# 서울사이버대학교(SCU) 콘텐츠 설계 및 품질검수 기준서

본 문서는 서울사이버대학교의 콘텐츠 설계 및 품질검수 지침(표현설계, 내용설계, 맞춤법, 출처 등)을 개발 및 검수 시스템(`SB-Design`)에서 참조할 수 있도록 표준화한 규격 정의서입니다.

---

## 1. 슬라이드 및 화면 규격 (표현설계)

- **슬라이드 규격**: 사용자 지정, **가로 33.867cm × 세로 19.05cm (16:9 와이드)**, 가로 방향
- **상단 타이틀바 디자인 범위**: 좌 0, 우 0, 상 0, 하 7.8cm 이내
- **슬라이드 내용 배치 가능 범위**:
  - [교수 우측 위치] 전자칠판형, 크로마형: 좌 16, 우 6.5, 상 7.2, 하 8.5
  - [교수 중앙 위치] 크로마형: 좌 16, 우 16, 상 7.2, 하 8.5 (교수 영상 위치 제외)
  - [내용 전체화면] 전자칠판형, 크로마형, 화면녹화형, 손글씨형: 좌 16, 우 15, 상 7.2, 하 8.5

---

## 2. 폰트 및 텍스트 규격

- **기본 폰트**: 맑은고딕 또는 나눔스퀘어 계열 (나눔스퀘어, 나눔스퀘어B, 나눔스퀘어EB)
- **가독성 원칙**:
  - 가독성 확보를 위해 **모든 본문 글씨는 Bold(볼드체)** 적용
  - 페이지 내 **가장 작은 폰트 크기는 20pt 이상** (출처 표기 제외)
  - 본문 줄간격: **최소 배수 1.1 이상**
  - 일반 학습 내용 본문 폰트 기본 색상: **RGB 45, 45, 45 (`#2D2D2D`)**
- **콘텐츠 위계별 권장 폰트 규정**:
  1. 슬라이드명: 나눔스퀘어EB, 32pt
  2. 1수준 제목 (대제목/장제목): 나눔스퀘어EB, 24pt
  3. 2수준 제목 (중제목/절제목): 나눔스퀘어B, 21pt
  4. 학습내용 (본문): 나눔스퀘어B, 20pt 이상
  5. 중요 키워드: 나눔스퀘어EB
  6. 출처 표기: 나눔스퀘어B, 12pt

## 3. 내용 설계 및 교수설계 지침

1. **내용 누락 및 불일치**:
   - 원고의 핵심 개념/이론/학습내용이 SB에 누락되지 않아야 함
   - 과도한 요약 또는 문장 자름으로 인해 전달하려는 내용적 맥락이 왜곡되지 않아야 함
   - 원고와 SB 간 전문 용어, 인명, 고유명사 표기 불일치 금지
2. **정보과밀 방지 및 슬라이드 분할**:
   - 한 슬라이드에 너무 많은 텍스트를 빽빽하게 넣지 말고 적절한 여백 확보
   - 정보량이 과도할 경우 2개 이상의 슬라이드로 분할하거나 탭/팝업 인터랙션 적용 제안
3. **교수설계 논리**:
   - **학습목표**: 불분명한 진술 금지, 명확한 행동 목표로 수정 진술, 블릿 체계 사용
   - **학습개요**: 학습목표(블릿 체계), 학습내용(번호 체계) 필수 포함
   - **목표 분류 표 규칙**: 목표 분류는 **"기억, 이해, 적용, 분석, 창안"** 중 하나만 들어올 수 있음. 학습목표를 기술한 동사의 의미를 살펴서 유사하면(예: `~설명할 수 있다`, `~요약할 수 있다` ➔ `이해`) 수정 요청 없이 그대로 둠.
   - **작업자 확인요청 말풍선(`To.교수님` 등)**: 외주업체 작업자가 교수자에게 확인을 요청하기 위해 추가해둔 것이므로 **오류(결함)가 아님**. 오류로 판정하지 않고 단순하게 **"확인요청 사항 있음"**으로만 별도 기록함.
   - **학습정리**: 
     - 유닛명과 동일한 위계 유지
     - **원고 반영 시 정상 판정**: 원고에 이미 학습정리 내용이 존재하고 SB가 이를 충실히 반영하여 작성했다면 **오류(결함)가 아님** (오류 지적 및 건수 합계 제외, 더 풍부한 요약을 원할 때 참고할 수 있는 선택적 권고 문안으로만 제시 가능)
     - **원고 내용 부재 시**: 원고에 학습정리 내용이 아예 없거나 비어있는 경우에만 결함으로 판정하며, 비워두지 말고 본문 중요 내용을 요약한 **"AI 추천 완성형 문안"**을 반드시 직접 작성하여 제시 (교수 확인 요청 메모로 대체 금지)
   - **퀴즈/평가**: 정오답 표기, 문제 해설, 피드백, 관련학습 보기 필수 포함
   - **제목 규칙**: 슬라이드 제목은 2줄 초과 금지 (2줄 이상일 경우 1줄로 요약 후 하단에 11pt로 괄호 부연 설명)
   - **주차 간 연속성**: 이전 주차에서 변경된 디자인 시안, 템플릿(유닛명 간지 등) 규칙이 후속 주차에도 누락 없이 일관되게 적용되었는지 확인
   - **목차 표 전체화면**: 2번 슬라이드 목차 표 하단의 전체화면 슬라이드 안내는 해당 슬라이드가 없을 경우 '없음'으로 기재하거나 행 삭제
4. **인터랙션 및 시각화(도해화)**:
   - 교안 내용을 도형 구성 없이 '텍스트로만' 나열하는 것 지양
   - 내용 맥락에 맞는 다이어그램 도해화 적용:
     - 인과 관계: `A → B`
     - 병렬 관계: `A : B`
     - 종속 관계: `A ⊃ B, C`
     - 대립 관계: `A ↔ B`
   - 화면 대부분을 비워놓고 클릭 시 내용이 나타나는 불필요한 인터랙션 금지
   - 탭 박스 사용 시 첫 번째 탭의 내용이 디폴트로 제시되어야 함
   - 클릭/행동 유발 시 명확한 지시문 필수 제시 (예: `※ 하단의 각 탭을 클릭하여 내용을 확인하세요.`)

## 4. 맞춤법, 문장 종결법 및 출처 표기 지침

1. **서술형 종결 문장 마침표 원칙**:
   - 서술형 종결 문장에만 마침표 사용 (`~다.`, `~요.` **O**)
   - 명사형/개조식 종결어미에는 마침표 금지 (`~임`, `~함`, `~것` **O** / `~임.`, `~함.` **X**)
2. **괄호 부가설명 문장 마침표 위치**:
   - 괄호로 부가 설명이 있는 문장의 끝에서 마침표는 **반드시 괄호 뒤에 표기** (`본 지침을 적용한다(2026).` **O** / `...적용한다.(2026)` **X**)
3. **단어 잘림 방지**:
   - 줄바꿈 시 한글/영어 단어가 중간에 잘려 다음 줄로 넘어가지 않도록 파워포인트 단어 잘림 방지 설정 준수
4. **저작권 및 출처 표기 규격**:
   - 모든 저작물(이미지, 표, 그래프, 영상) 우측 하단에 `#1, #2, ...` 형태로 표기
   - **본문 텍스트 내 `#1`, `# 1` 표기**: 슬라이드 노트의 출처 번호와 연결하는 정식 출처 인용 앵커 표시이므로 정상 표기임 (텍스트 누락 오류로 오탐 금지)
   - **소형 이미지/아이콘 출처 면제**: 모든 이미지가 출처 표시 대상은 아님. 통상 전구, 화살표, 가방, 픽토그램 등 장식용 소형 아이콘은 출처 표시가 없어도 무방함
   - 슬라이드 노트 또는 개발 페이지에 `#출처/N : 저작자명, 저작물명, 출판사, 연도, 페이지` 상세 정보 명시
   - 유료 라이선스 이미지 사용 시 라이선스 번호 표기 (예: `구매이미지 : GettyImages-XXXXXXXXXX`)
5. **'화면설명' 영역 검수 완전 제외 (필수)**:
   - 슬라이드 우측 상단 '화면설명' 영역에 들어간 내용은 설계자/작업자가 연출 및 작업 설명글을 적어둔 공간이므로, 해당 영역의 텍스트, 서식, 플레이스홀더, 오탈자 등은 **모두 검수 대상에서 완전히 제외**함 (오류 지적 및 건수 절대 제외)
6. **말풍선('To.교수님') 확인요청 및 내용 검수 원칙**:
   - 말풍선 개체 자체는 오류가 아니며, 해당 슬라이드에는 파워포인트 메모(Comment)에 **"확인요청 사항 있음"**을 반드시 기재함
   - **단, 말풍선 안의 변명이나 사유와 무관하게, 슬라이드 본문/표 내용이 원고와 대조하여 불일치·왜곡·누락된 것이 있다면 반드시 정상적으로 내용 오류로 지적해야 함**

## 5. 검수 피드백 작성 원칙: "누구나 바로 알아듣는 쉬운 실무 지침"

본 시스템을 재사용하는 모든 검수자 및 AI 에이전트는 지적사항 및 수정요청을 작성할 때 **추상적인 학술 용어, 평론가적 표현을 일체 배제**하고, 현업 제작자가 즉시 파워포인트에서 손을 움직일 수 있는 **초등학생도 이해하는 구체적인 행동 지시어**로 작성해야 합니다.

### 1) 작성 가이드라인 (Before vs After)
- **학습목표 지적 시**:
  - ❌ (어려운 표현): "핵심 행동목표가 모호하므로 도달 행동을 명확히 진술 권고"
  - ⭕ (쉬운 실무 표현): **"'~을 이해할 수 있다'를 '~을 설명할 수 있다'로 바꿔주세요."**
- **도해화/시각화 지적 시**:
  - ❌ (어려운 표현): "텍스트 나열을 지양하고 판매장소 vs 판매전략 대비 구조로 도해화 제안"
  - ⭕ (쉬운 실무 표현): **"텍스트 한 줄만 덜렁 두지 마세요. 아래에 박스 2개를 나란히 만들고 [왼쪽: 판매장소 선택 X], [오른쪽: 판매전략 선택 O]로 명확히 대비되게 넣어주세요."**
- **제목 및 서브타이틀 지적 시**:
  - ❌ (어려운 표현): "서브타이틀 일관성 및 대등 구조 유지 검토"
  - ⭕ (쉬운 실무 표현): **"슬라이드 위쪽 서브타이틀 박스에 'Amazon에서 중요한 질문'이라고 제목을 딱 붙여주세요."**
- **학습정리 지적 시**:
  - ❌ (어려운 표현): "학습정리 내용 부재로 인한 지침서 미준수"
  - ⭕ (쉬운 실무 표현): **"학습정리가 비어있습니다. 비워두지 마시고 '1. 글로벌 플랫폼 6대 유형 이해, 2. 주요 플랫폼 비교'와 같이 바로 복사해 넣을 수 있는 완성형 문장을 직접 적어주세요."**
- **레이아웃/화면 이탈 지적 시**:
  - ❌ (어려운 표현): "개체가 슬라이드 바운더리를 오버플로우하여 안전 영역 침범"
  - ⭕ (쉬운 실무 표현): **"오른쪽 박스가 슬라이드 화면 밖으로 삐져나갔습니다. 박스 가로 너비를 줄여서 화면 안으로 쏙 들여놓아 주세요."**

### 2) 톤앤매너
- 읽는 즉시 고민 없이 PPT를 수정할 수 있도록 **친절하고 명쾌한 실무 지침투(`~로 바꿔주세요`, `~박스를 넣어주세요`, `~삭제해 주세요`)**를 사용합니다.
